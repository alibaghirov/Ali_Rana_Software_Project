1. Project Overview

Qənaət is a localized smart personal finance and micro-savings web platform developed specifically for the Azerbaijani market (AZN). In everyday financial management, individuals often lack clarity on how much discretionary money they can safely spend after accounting for upcoming commitments, while impulsive withdrawals frequently sabotage long-term savings intentions. Qənaət eliminates this friction by answering five immediate daily financial questions at a glance, connecting to local open banking APIs with automated transaction deduplication, and dynamically calculating exact daily saving contributions toward user-defined goals. To safeguard financial commitments, the platform introduces an anti-impulse cooling-off safety lock on withdrawals and reinforces daily discipline through a habit-building gamification streak engine.

Primary Users:

  • Everyday Savers and Young Professionals: Need an intuitive, AZN-denominated expense tracker that imports card transactions from local banks and categorizes spending without tedious manual ledger entry.
  • Goal-Oriented Individuals and Students: Need structured, algorithmic guidance on how much to deposit daily toward specific life milestones (e.g., tech purchases, emergency fund, tuition) paired with withdrawal cooling-off locks to curb impulse spending.
  • Household Budgeters and Financial Planners: Need comprehensive month-over-month cash flow summaries, spending breakdowns by category, multi-user workspace switching, and authenticated CSV data exports.

Main System Features:

  • 5-Question Instant Financial Dashboard: Delivers instant clarity on total account balance, unallocated available cash, monthly earnings, monthly expenses, and net cash flow health.
  • Dynamic Daily Savings Recommendation Engine: Automatically computes the exact daily contribution required for each goal based on target amount, accumulated balance, and days remaining until deadline.
  • Anti-Impulse Savings Security Lock (Soyuma Müddəti): Prevents spontaneous dipping into savings goals by enforcing an intentional cooling-off waiting period before funds can be withdrawn.
  • Open Banking Integration with Automated Deduplication: Ingests transaction feeds from Azerbaijani banks (Kapital Bank, ABB, Leo, CBAR sandbox) and filters duplicate incoming records.
  • Discipline Gamification & Review Streak Tracker: Motivates consistent daily financial tracking by awarding consecutive day streak counters, milestone badges (10, 20, 30, 40, 100 days), and experience levels.
  • Comparative Monthly Analytics & CSV Export: Displays month-over-month variances in revenue and expenses alongside visual category distribution charts, with one-click authenticated CSV download.
  • Secure Multi-Factor Authentication: Authenticates users through mobile phone numbers, national FİN codes, and time-expiring 6-digit SMS OTP verification.

4. Monitoring and Alerting

To guarantee high availability and early anomaly detection, Qənaət incorporates an automated monitoring and alerting subsystem. The system continuously tracks: (1) backend service availability and HTTP response latencies; (2) server error spikes (HTTP 500 status rates); (3) suspicious authentication behavior such as repeated failed OTP or FİN attempts; (4) open banking connector disconnections or synchronization failures; and (5) AI inference timeouts.

How it works: (1) Operational events and performance telemetry are captured in real time through Express middleware, health check endpoints, and unhandled exception hooks; (2) Rule evaluators compare metrics against predefined failure thresholds; (3) When an anomaly or threshold violation is detected, an asynchronous dispatcher invokes the Telegram Bot API webhook; (4) The Telegram bot formats and transmits an urgent markdown alert directly to the team's dedicated engineering channel.

Secret Management: In compliance with security best practices, the Telegram bot token (TELEGRAM_BOT_TOKEN) and destination chat identifier (TELEGRAM_CHAT_ID) are strictly isolated inside a local .env file. This file is loaded at runtime through secure environment configuration and is explicitly registered in .gitignore, ensuring credentials are never committed to the public Git repository.
